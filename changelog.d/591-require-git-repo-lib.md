- New `tools/lib/require-git-repo.sh` (`keel_is_git_work_tree`, `keel_is_git_repo`, `keel_require_git_work_tree`) is now the one "is this a git checkout?" check: `tools/branch-cleanup.sh`, `tools/doctor.sh`, `tools/audit-packet/export.sh`, `tools/delta-audit/derive.sh`, `tools/drydock/inventory.sh`, `tools/self/prose-drift.sh` and the shared `tools/lib/repo-arg-guard.sh` (so `tools/install-read-trace.sh`, `tools/install-pre-pr-gate.sh`, `tools/install-machine-watch.sh`) call it, and `tools/install-secret-guard.sh` carries an inline copy (it ships standalone). Each used to hand-roll the check; the exit-status-only `rev-parse --is-inside-work-tree` variants let a bare repository through (git exits 0 printing `false`), so `install-secret-guard.sh`, `install-read-trace.sh`, `install-pre-pr-gate.sh`, `install-machine-watch.sh`, `drydock/inventory.sh`, `delta-audit/derive.sh` and `audit-packet/export.sh` now refuse a bare repo with their existing message, and `doctor.sh` reports one as `G-GIT-MISSING`; `branch-cleanup.sh` still accepts any repository. The shared gate reads git's `true` output, cannot abort the caller silently under `set -e`, and passes git's own "dubious ownership" diagnostic through instead of relabelling it as "not a git repo" (the wording for a plain non-repo and a bare repo is unchanged). `install-secret-guard.sh --where` now also refuses a bare repo. `tools/init-project.sh`, `tools/self/tag-ready.sh` and `tools/self/bypass-scan.sh` keep their own checks (dir #591).
